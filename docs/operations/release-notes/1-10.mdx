> [!NOTE]
> For general upgrade procedures, see the [Upgrade Overview](/operations/upgrades/overview/).

UDS Core 1.10 removes the implicit Keycloak `preview` feature group from the default startup configuration. Deployments that depend on preview features must enable them explicitly through `keycloak.keycloak.features.additional`.

### ⚠ Breaking changes

| Change | Impact | Action required |
|---|---|---|
| UDS Core no longer enables Keycloak's generic `preview` feature group by default. | Keycloak preview features that UDS Core previously enabled indirectly, including `stateless:v1` in Keycloak 26.7, remain disabled unless you configure them explicitly. | Review deployments that rely on preview features. Add the specific feature names to `keycloak.keycloak.features.additional` before upgrading, or add `preview` only when you intentionally require every preview feature. |

### Notable features

- **Explicit Keycloak feature selection:** UDS Core exposes the `keycloak.keycloak.features.additional` value for additional features and no longer passes `preview` by default. This prevents newly added Keycloak preview features from activating during a UDS Core upgrade. See the [identity and authorization configuration reference](/reference/configuration/identity-and-authorization/#keycloak-features) ([#2838](https://github.com/defenseunicorns/uds-core/pull/2838)).

### Dependency updates

This feature change does not update a runtime dependency.

## Upgrade considerations

### Keycloak session behavior

Because stateless mode is no longer enabled by default in this release, active Keycloak login sessions and action tokens may not carry over during the upgrade. Some users may need to sign in again.

### Pre-upgrade steps

<Steps>

1. **Review Keycloak feature dependencies**

   If your deployment relies on a Keycloak feature that UDS Core previously enabled through the generic `preview` group, add that feature to `keycloak.keycloak.features.additional` before upgrading. Prefer the specific feature name over `preview` so unrelated preview features do not activate.

</Steps>

### Post-upgrade verification

<Steps>

1. **Verify Keycloak startup and SSO flows**

   Confirm that the Keycloak StatefulSet becomes ready and test the SSO flows used by your deployment. If you enabled an additional feature, verify its expected behavior separately.

</Steps>
