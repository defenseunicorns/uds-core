> [!NOTE]

UDS Core 1.11 expands classification banner configuration so operators can apply different banner text and footer behavior by host and path. This release also exposes Pepr admission webhook annotations through Zarf values, fixes several upgrade and templating issues, and bumps UDS Identity Config to 0.30.0 for registration and client policy fixes.

### Notable features

- **Multiple classification banners:** UDS Core now supports a `classificationBanners` list with per-entry `text`, `addFooter`, `enabledHosts`, and optional `pathPrefixes` values. The legacy `classificationBanner` value remains supported, but emits a deprecation note when enabled. See [Enable the classification banner](/how-to-guides/platform-features/enable-classification-banner/) ([#2851](https://github.com/defenseunicorns/uds-core/pull/2851)).
- **Pepr webhook annotation overrides:** Base and Standard package schemas now expose `.pepr-uds-core.module.admission.webhookAnnotations`, allowing operators to set admission webhook annotations through Zarf values ([#2886](https://github.com/defenseunicorns/uds-core/pull/2886)).
- **Functional layer Zarf values:** The backup-restore and metrics-server functional layers now include default Zarf values and generated schemas, matching the configuration surface exposed by the larger packages. See the [Zarf values reference](/reference/configuration/zarf-values/) ([#2867](https://github.com/defenseunicorns/uds-core/pull/2867)).
- **Checkpoint restore stability:** Checkpoint packages now remove persisted node IP state before creating checkpoints, preventing restore failures when k3d assigns the restored server a different address ([#2881](https://github.com/defenseunicorns/uds-core/pull/2881)).
- **Istio ambient gateway readiness:** UDS Core now waits for Pepr admission Pods to become ready and ambient-enabled before deploying Istio gateways, reducing intermittent admission webhook `EOF` failures during startup and upgrades ([#2871](https://github.com/defenseunicorns/uds-core/pull/2871)).
- **Keycloak PDB templating fix:** The Keycloak `PodDisruptionBudget` template now renders correctly when enabled ([#2878](https://github.com/defenseunicorns/uds-core/pull/2878)).

## Upgrade considerations

### Pepr 2.0 compatibility

UDS Core packages Pepr 2.0 in this release. No manual platform upgrade step is expected for standard UDS Core deployments, but operators who maintain custom Pepr modules or repo automation should review the [Pepr 2.0.0 release](https://github.com/defenseunicorns/pepr/releases/tag/v2.0.0), especially the removal of `pepr format`.

### Identity Config updates (0.30.0)

Identity Config [0.30.0](https://github.com/defenseunicorns/uds-identity-config/releases/tag/v0.30.0) includes the following changes. No manual realm steps are required for existing clusters.

- **Non-CAC registration password validation:** Non-CAC registration now enforces Keycloak password validation when email verification is enabled. CAC registration remains password-optional ([#905](https://github.com/defenseunicorns/uds-identity-config/pull/905)).
- **Client policy full-scope handling:** The UDS client policy no longer blocks setting `fullScopeAllowed` on clients ([#901](https://github.com/defenseunicorns/uds-identity-config/pull/901)).
