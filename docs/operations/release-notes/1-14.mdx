UDS Core 1.14 adds keyless signatures to published Core packages and UDS CLI Next demo bundles. This release also adds default disruption budgets for HA Keycloak deployments, rejects conflicting HTTP expose routes across namespaces, and improves HTTP/2 gateway routing.

> [!WARNING]
> UDS Core 1.12 through 1.14 may disrupt login through an additional Keycloak SSO hostname. See [Known issue: additional Keycloak SSO hostnames](#known-issue-additional-keycloak-sso-hostnames) before upgrading. UDS Core 1.14.0 also has a known issue with CAC login flows and it is recommended that you upgrade directly to 1.14.1.

### ⚠ Breaking changes

| Change                              | Impact                                                                                                                                                                                                                                          | Action required                                                                                                                                                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HA-only Keycloak disruption budgets | Upgrades remove existing chart-managed PodDisruptionBudgets (PDBs) when `autoscaling.enabled` is `false`. The chart now defaults to `maxUnavailable: 1` and rejects configurations that also set `minAvailable`, even when the PDB is disabled. | Configure an external PostgreSQL database and enable autoscaling if you require a chart-managed PDB. Set `podDisruptionBudget.maxUnavailable` to `null` when using `minAvailable` ([#2980](https://github.com/defenseunicorns/uds-core/pull/2980)). |

### Notable features

- **Signed release artifacts:** Published standard and functional layer Core packages now carry keyless signatures backed by GitHub OIDC. The upstream `k3d-core-demo-next` and `k3d-core-slim-dev-next` bundles also carry signatures for both amd64 and arm64. Publishing verifies signatures before uploading the artifacts ([#2945](https://github.com/defenseunicorns/uds-core/pull/2945), [#2972](https://github.com/defenseunicorns/uds-core/pull/2972)).
- **Default Keycloak HA disruption budget:** Enabling `autoscaling.enabled` now creates a PDB with `maxUnavailable: 1` and `unhealthyPodEvictionPolicy: AlwaysAllow`. Set `podDisruptionBudget.enabled` to `false` to disable it in HA mode. See [Keycloak high availability](/how-to-guides/high-availability/keycloak/) ([#2980](https://github.com/defenseunicorns/uds-core/pull/2980)).
- **HTTP expose collision validation:** The UDS Operator now rejects `Package` creates and updates when HTTP routes in different namespaces share a gateway and hostname and either route is a catch-all. Both routes can share a host when their `advancedHTTP.match` entries constrain routing ([#2783](https://github.com/defenseunicorns/uds-core/pull/2783)).
- **HTTP 421 filter change (reverted in 1.14.1):** In 1.14.0, the misdirected-request filter permitted HTTP/2 connection reuse when the requested host had a route on the selected gateway listener ([#2997](https://github.com/defenseunicorns/uds-core/pull/2997)). Version 1.14.1 reverts this behavior to fix the [CAC login regression](#known-issue-cac-login-from-tenant-application).
- **Velero network access:** Set `velero.uds-velero-config.additionalNetworkAllow` to add custom `network.allow` entries to the Velero `Package`. See [Configure Core network access](/how-to-guides/networking/configure-core-network-access/) ([#2977](https://github.com/defenseunicorns/uds-core/pull/2977)).
- **Stable UDPRoute API:** The UDS Operator now generates UDP routes using `gateway.networking.k8s.io/v1` instead of `v1alpha2`. See [Expose UDP applications](/how-to-guides/networking/expose-udp-apps/) ([#2999](https://github.com/defenseunicorns/uds-core/pull/2999)).
- **Keycloak security update:** Keycloak 26.7.4 includes upstream security fixes and bug fixes. UDS Identity Config remains at `0.32.0`, the version already included in UDS Core 1.13.1 ([#2969](https://github.com/defenseunicorns/uds-core/pull/2969), [Keycloak release notes](https://github.com/keycloak/keycloak/releases/tag/26.7.4)).

## Upgrade considerations

> [!IMPORTANT]
> Upgrade to 1.14.1 to fix the Common Access Card (CAC) login regression in 1.14.0. This patch restores the previous behavior, ensuring CAC login flows work regardless of entrypoint ([#3068](https://github.com/defenseunicorns/uds-core/pull/3068)).

### Known issue: CAC login from tenant applications

UDS Core 1.14.0 changed the misdirected-request filter to allow HTTP/2 connection reuse when the requested host has a route on the selected gateway listener ([#2997](https://github.com/defenseunicorns/uds-core/pull/2997)). A browser can reuse a tenant application's `SIMPLE` TLS connection for `sso.<domain>`, bypassing the new TLS handshake that would request a client certificate under Keycloak's `OPTIONAL_MUTUAL` policy. Users may reach Keycloak without a CAC certificate prompt and cannot complete CAC login. This issue is resolved in 1.14.1.

Until you are able to upgrade, quit and reopen the browser, then navigate directly to `https://sso.<domain>` before opening a tenant application. Opening another SSO application in the same browser session may not restore the certificate prompt.

### Known issue: additional Keycloak SSO hostnames

UDS Core 1.12 introduced configured public and administrative Keycloak hostnames ([#2898](https://github.com/defenseunicorns/uds-core/pull/2898)). Deployments that route an additional public SSO hostname to the same Keycloak instance, such as a vanity or VDI login domain, may fail to complete login on UDS Core 1.12 through 1.14. Users have reported the error "Restart login cookie not found" when accessing the additional hostname. OIDC clients that use that hostname for discovery and issuer validation may also be affected.

If your deployment depends on an additional SSO hostname, test the complete login flow and token issuer validation in a non-production environment before upgrading. Defer the production upgrade if that flow fails, and contact Product Support. A generally applicable fix has not yet been validated.

### Pre-upgrade steps

Before upgrading, review these changes:

<Steps>

1. **Configure Core package signature verification**

   Add `keylessVerification` to every Core package reference in your bundle, including functional layers:

   ```yaml title="uds-bundle.yaml"
   packages:
     - name: core
       repository: registry.defenseunicorns.com/public/core
       ref: 1.14.0-upstream
       keylessVerification:
         # Accept Core release tags signed by the publishing workflow
         certificateIdentityRegexp: ^https://github\.com/defenseunicorns/uds-core/\.github/workflows/publish\.yaml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$
         certificateOIDCIssuer: https://token.actions.githubusercontent.com
   ```

   For layer examples, see [Build a functional layer bundle](/how-to-guides/platform-features/build-functional-layer-bundle/).

2. **Review Keycloak PDB overrides**

   To retain a chart-managed PDB with autoscaling currently disabled, configure an external PostgreSQL database and set `autoscaling.enabled` to `true`. If you use `podDisruptionBudget.minAvailable`, set `podDisruptionBudget.maxUnavailable` to `null`. See [Keycloak high availability](/how-to-guides/high-availability/keycloak/) for setup and node-drain precautions.

3. **Resolve conflicting HTTP expose entries**

   Review `Package` resources in different namespaces that share a gateway and hostname. Use distinct hosts or gateways, or constrain both routes with `advancedHTTP.match`, such as URI paths. Catch-all routes can block subsequent `Package` updates. See [Expose applications on gateways](/how-to-guides/networking/expose-apps-on-gateways/) ([#2783](https://github.com/defenseunicorns/uds-core/pull/2783)).

4. **Review custom Grafana overrides**

   If you customize Grafana containers or commands, review the [chart changes](https://github.com/grafana-community/helm-charts/compare/grafana-12.7.2...grafana-13.2.6). Grafana, dashboard download, and sidecar containers now default to `readOnlyRootFilesystem: true`; mount writable paths where needed.

</Steps>
