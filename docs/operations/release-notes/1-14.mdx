UDS Core 1.14 adds keyless signatures to published Core packages and UDS CLI Next demo bundles. This release also adds default disruption budgets for HA Keycloak deployments, rejects conflicting HTTP expose routes across namespaces, and improves HTTP/2 gateway routing.

### ⚠ Breaking changes

| Change                               | Impact                                                                                                                                                                                                                                              | Action required                                                                                                                                                                                                                                     |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Signed Core packages                 | Published standard and functional layer Zarf packages now require signature verification configuration when you consume them in a UDS bundle.                                                                                                       | Add `keylessVerification` to each Core package reference before upgrading. See the pre-upgrade steps below ([#2945](https://github.com/defenseunicorns/uds-core/pull/2945)).                                                                        |
| HA-only Keycloak disruption budgets  | Upgrades remove existing chart-managed PodDisruptionBudgets (PDBs) when `autoscaling.enabled` is `false`. The chart now defaults to `maxUnavailable: 1` and rejects configurations that also set `minAvailable`, even when the PDB is disabled.     | Configure an external PostgreSQL database and enable autoscaling if you require a chart-managed PDB. Set `podDisruptionBudget.maxUnavailable` to `null` when using `minAvailable` ([#2980](https://github.com/defenseunicorns/uds-core/pull/2980)). |
| HTTP expose collision validation     | The UDS Operator rejects `Package` creates and updates when entries in different namespaces use the same gateway and fully qualified domain name (FQDN), and either entry is a catch-all.                                                           | Use distinct hosts or gateways, or configure `advancedHTTP.match` on both routes to constrain routing ([#2783](https://github.com/defenseunicorns/uds-core/pull/2783)).                                                                             |
| Grafana Helm chart security defaults | The chart now sets `readOnlyRootFilesystem: true` for Grafana, dashboard download, and sidecar containers, and tightens test and image-renderer security contexts. Custom containers or commands that depend on writable root filesystems may fail. | Review custom Grafana overrides and mount writable paths explicitly where needed ([upstream chart changes](https://github.com/grafana-community/helm-charts/compare/grafana-12.7.2...grafana-13.2.6)).                                              |

### Notable features

- **Signed release artifacts:** Published standard and functional layer Core packages now carry keyless signatures backed by GitHub OIDC. The upstream `k3d-core-demo-next` and `k3d-core-slim-dev-next` bundles also carry signatures for both amd64 and arm64. Publishing verifies signatures before uploading the artifacts ([#2945](https://github.com/defenseunicorns/uds-core/pull/2945), [#2972](https://github.com/defenseunicorns/uds-core/pull/2972)).
- **Default Keycloak HA disruption budget:** Enabling `autoscaling.enabled` now creates a PDB with `maxUnavailable: 1` and `unhealthyPodEvictionPolicy: AlwaysAllow`. Set `podDisruptionBudget.enabled` to `false` to disable it in HA mode. See [Keycloak high availability](/how-to-guides/high-availability/keycloak/) ([#2980](https://github.com/defenseunicorns/uds-core/pull/2980)).
- **More precise HTTP 421 protection:** The misdirected-request filter now permits HTTP/2 connection reuse when the requested host has a route on the selected gateway listener. Requests whose authority differs from the TLS Server Name Indication (SNI) and has no matching route still receive HTTP 421 ([#2997](https://github.com/defenseunicorns/uds-core/pull/2997)).
- **Velero network access:** Set `velero.uds-velero-config.additionalNetworkAllow` to add custom `network.allow` entries to the Velero `Package`. See [Configure Core network access](/how-to-guides/networking/configure-core-network-access/) ([#2977](https://github.com/defenseunicorns/uds-core/pull/2977)).
- **Stable UDPRoute API:** The UDS Operator now generates UDP routes using `gateway.networking.k8s.io/v1` instead of `v1alpha2`. See [Expose UDP applications](/how-to-guides/networking/expose-udp-apps/) ([#2999](https://github.com/defenseunicorns/uds-core/pull/2999)).
- **Keycloak security update:** Keycloak 26.7.4 includes upstream security fixes and bug fixes. UDS Identity Config remains at `0.32.0`, the version already included in UDS Core 1.13.1 ([#2969](https://github.com/defenseunicorns/uds-core/pull/2969), [Keycloak release notes](https://github.com/keycloak/keycloak/releases/tag/26.7.4)).

## Upgrade considerations

### Pre-upgrade steps

Before upgrading, review package verification, Keycloak overrides, and HTTP expose entries:

<Steps>

1. **Configure Core package signature verification**

   Add the following verification block to every standard or functional layer Core package reference in your bundle. Release signatures use the tagged `publish.yaml` workflow identity and GitHub's OIDC issuer:

   ```yaml title="uds-bundle.yaml"
   packages:
     - name: core
       repository: registry.defenseunicorns.com/public/core
       ref: 1.14.0-upstream
       keylessVerification:
         # Accept Core release tags signed by the publishing workflow
         certificateIdentityRegexp: ^https://github\.com/defenseunicorns/uds-core/\.github/workflows/publish\.yaml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$
         certificateOIDCIssuer: https://token.actions.githubusercontent.com
   ```

   See [Build a functional layer bundle](/how-to-guides/platform-features/build-functional-layer-bundle/) for examples covering individual Core layers.

2. **Review Keycloak PDB overrides**

   If you require an existing chart-managed PDB outside HA mode, configure an external PostgreSQL database and set `autoscaling.enabled` to `true` before upgrading. Follow [Keycloak high availability](/how-to-guides/high-availability/keycloak/) for the database and autoscaling configuration.

   If you use `minAvailable`, clear the new `maxUnavailable` default. Add this override under the existing Core package reference in your bundle:

   ```yaml title="uds-bundle.yaml"
   overrides:
     keycloak:
       keycloak:
         values:
           # Remove the default when retaining your existing minAvailable override
           - path: podDisruptionBudget.maxUnavailable
             value: null
   ```

   HA deployments need schedulable capacity for replacement pods during a node drain. If replacement capacity is unavailable, the PDB can block the drain after the first eviction. Add capacity before maintenance, or set `podDisruptionBudget.enabled` to `false` before draining and re-enable it after capacity returns.

3. **Resolve conflicting HTTP expose entries**

   Review `Package` resources in different namespaces that share the same gateway and FQDN. Use distinct hosts or gateways, or give both routes effective `advancedHTTP.match` conditions, such as URI paths. An empty match remains a catch-all. Existing conflicts can prevent subsequent `Package` updates. See [Expose applications on gateways](/how-to-guides/networking/expose-apps-on-gateways/).

4. **Review custom Grafana overrides**

   Check custom commands and containers against the chart's new filesystem and security defaults. Use explicit writable mounts for paths your customization writes to. UDS Core continues to set explicit Grafana image tags for each flavor; the upstream chart's default distroless image tag does not replace those tags.

</Steps>
