UDS Core 1.15 restores login and issuer validation through additional Keycloak SSO hostnames while hardening Keycloak ingress handling. This release also improves checkpoint startup and Prometheus upgrade reliability, and adds redirect prefix rewriting to the `Package` CR.

### Notable features

- **Additional Keycloak SSO hostnames:** Keycloak now derives its public hostname from trusted request data instead of fixed hostname settings. This restores discovery, login, token issuer validation, and protected application sessions through additional SSO hostnames, resolving the known issue in UDS Core 1.12 through 1.14 ([#3044](https://github.com/defenseunicorns/uds-core/pull/3044)).
- **Keycloak ingress hardening:** Core-managed Keycloak routes now remove untrusted forwarding headers, set trusted HTTPS forwarding values, add HTTP Strict Transport Security (HSTS) with `includeSubDomains`, and vary responses by origin. The Keycloak affinity cookie now also uses the `Secure` attribute. Grafana declares its exact HTTPS SSO origin while retaining login and logout redirects ([#3000](https://github.com/defenseunicorns/uds-core/pull/3000)).
- **Checkpoint startup reliability:** The checkpoint development package now reduces K3s node status reporting intervals and isolates Istio CNI configuration from Flannel startup rewrites. These changes prevent startup races that could exceed the deployment readiness timeout ([#3039](https://github.com/defenseunicorns/uds-core/pull/3039)).
- **Prometheus upgrade reliability:** Prometheus now gives a newly created `config-reloader` container time to install its termination handler before Kubernetes replaces the Pod during rapid StatefulSet revisions. This prevents terminating Pods from blocking the final Prometheus revision during upgrades ([#3077](https://github.com/defenseunicorns/uds-core/pull/3077)).
- **Redirect prefix rewriting:** Set `spec.network.expose[].advancedHTTP.redirect.prefixRewrite` on a `Package` to replace the matched path prefix in an HTTP redirect. UDS Core adds this field through the Istio 1.31.1 schema update ([#3067](https://github.com/defenseunicorns/uds-core/pull/3067)).

## Upgrade considerations

### Identity Config updates (0.32.2)

UDS Identity Config [0.32.2](https://github.com/defenseunicorns/uds-identity-config/releases/tag/v0.32.2) restores multi-domain and claim token behavior affected by earlier hostname changes. This release also includes plugin and dependency updates. No manual realm steps are required for existing clusters.
