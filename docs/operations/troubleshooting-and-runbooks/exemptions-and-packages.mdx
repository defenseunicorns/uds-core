## When to use this runbook

Use this runbook when changes to a `Package` or `Exemption` do not produce the expected resources or admission behavior.

## Overview

The Core Go controller reconciles Packages and compiles Exemptions into a protected admission snapshot. Unavailable dependencies, invalid configuration, or an unhealthy controller can prevent convergence. An invalid exemption input revokes the compiled grants and sets `spec.valid: false`; Core does not continue using stale exemptions.

## Pre-checks

<Steps>

1. **Check the Core controller**

   Inspect readiness and recent errors:

   ```bash
   uds zarf tools kubectl get pods -n uds-system -l app=uds-controller
   uds zarf tools kubectl logs -n uds-system deploy/uds-controller --all-pods=true --tail=100
   ```

   Look for unavailable API resources, failed reconciliation, identity dependencies, or `Native admission input compilation failed` errors.

2. **Check Package status**

   Inspect the requested generation and observed result:

   ```bash
   uds zarf tools kubectl get package -n <namespace> <package-name> -o yaml
   ```

   `status.phase` should reach `Ready`, and `status.observedGeneration` should match `metadata.generation`. Inspect errors when the phase is `Retrying`, `Failed`, or `RemovalFailed`.

3. **Check the exemption and protected snapshot**

   Inspect the source resource and the compiled result:

   ```bash
   uds zarf tools kubectl get exemptions -n uds-policy-exemptions -o yaml
   uds zarf tools kubectl get admissionparameters.policy.uds.dev -n uds-policy-exemptions uds-native-grants -o yaml
   ```

   The protected snapshot should have `spec.valid: true` and a revision. Create Exemptions in `uds-policy-exemptions` unless the cluster operator has [enabled all namespaces](/how-to-guides/policy-and-compliance/allow-exemptions-all-namespaces/).

</Steps>

## Procedure

### Cause 1: Unhealthy controller or dependencies

Inspect Pod events to identify scheduling, image, memory, or configuration failures:

```bash
uds zarf tools kubectl describe pods -n uds-system -l app=uds-controller
```

Correct the reported cause. If a restart is necessary after fixing it, restart only Core's controller and wait for readiness:

```bash
uds zarf tools kubectl rollout restart deployment/uds-controller -n uds-system
uds zarf tools kubectl rollout status deployment/uds-controller -n uds-system
```

### Cause 2: Invalid resource or exemption scope

Compare the resource with the [Package specification](/reference/operator-and-crds/packages-v1alpha1-cr/) or [Exemption specification](/reference/operator-and-crds/exemptions-v1alpha1-cr/). Correct the source manifest and reapply it. Check policy names, namespace scope, and JavaScript regular expressions for exemption matchers. Do not edit the protected snapshot directly; the controller repairs it from source Exemptions.

Exemption changes apply to subsequent admission requests. Recreate or update a workload to exercise admission again; changing an Exemption does not rewrite existing Pods.

## Verification

Confirm Package generation and readiness, a valid current admission snapshot, and the expected outcome of a server-side dry run of your workload:

```bash
uds zarf tools kubectl get package -n <namespace> <package-name> -o yaml
uds zarf tools kubectl get admissionparameters.policy.uds.dev -n uds-policy-exemptions uds-native-grants -o yaml
uds zarf tools kubectl apply --dry-run=server -f <workload.yaml>
```

## Additional help

Collect the resource status, controller errors, and relevant Kubernetes events before opening a [UDS Core issue](https://github.com/defenseunicorns/uds-core/issues). Remove credentials and private certificate material from diagnostics.
